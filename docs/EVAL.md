## 2. 指标定义（口径定死，不准临时改）

| 指标 | 定义 | 实现位置 |
|---|---|---|
| 检测 Precision / Recall / Hmean | 预测框与标注框按 **IoU ≥ 0.5** 一对一匹配（贪心，按分数降序）；Hmean = 2PR/(P+R) | `backend/eval/metrics.py` |
| 字符准确率 | `1 − 编辑距离(预测, 标注) / 标注长度`，按行拼接后计算；空标注行不计 | 同上 |
| 字段级准确率 | 单字段 `normalized_value` 与标注**完全相等**为正确；分母 = 该字段有标注的样本数 | 同上 |
| 整单正确率 | 一张票据的**所有必填字段**都正确，才计为正确 | 同上 |
| 待确认率 | `need_review=true` 的字段数 / 总字段数 | 同上 |
| 低置信命中率 | 标为 `need_review` 且确实错误的字段数 / 标为 `need_review` 的字段数 | 同上 |
| 端到端耗时 | 上传请求返回到 `ocr_status=done` 的墙钟时间（含排队），报 P50 / P95 | 压测脚本（S7-1） |
| 密码运算耗时 | 单次运算均值 / 中位数 / P95，**先 warmup 再计时**，需记录 CPU 型号与版本 | `backend/eval/experiments/crypto_bench.py` |
| 防篡改检测率 | 篡改用例中被正确拒绝的比例 | `backend/tests/test_security.py` |

**必须写进论文的口径说明**：整单正确率必然显著低于字段级准确率（12 个字段各自 0.9 的准确率，整单只有约 0.28），
所以两个指标必须同时报告，并解释它们的关系。

## 3. 目标值（努力方向，不是承诺）

| 指标 | 目标 | 备注 |
|---|---|---|
| 检测 Hmean | ≥ 0.90 | 印章遮挡子集单独统计 |
| 字符准确率 | ≥ 0.92 | |
| 字段级准确率 | ≥ 0.85 | 12 字段均值 |
| 整单正确率 | ≥ 0.60 | 最诚实的指标 |
| 低置信命中率 | ≥ 0.80 | 用于校准阈值 |
| 端到端 P95 | ≤ 8s（CPU） | 上传 → 字段可确认 |
| SM2 签名 / 验签 | ≤ 20ms / ≤ 30ms | 单次平均 |
| SM4 加解密 2MB | ≤ 500ms（纯 Python） | 与 AES-GCM 对照时如实对比 |
| 防篡改检测率 | 100% | |
| 并发 5 路上传 | 0 失败 | |

> 达不到目标就写实测值 + 原因分析。**改测试集凑数字比达不到目标严重得多。**

## 6. 纪律

1. 数字只能来自 `backend/eval/results/` 里的真实 JSON，**一个数字对应一个文件**。
2. 每张图表下方必须能回答："多少样本、谁标的、怎么判对的"。
3. 负结果照写（例如"加入语义兜底仅提升 2 个百分点"），并给原因分析。
4. 换机器/换版本后旧数字作废，重新登记一节，不要覆盖历史。
5. 论文里不写"提升 X%"除非有对应的实验节编号。
