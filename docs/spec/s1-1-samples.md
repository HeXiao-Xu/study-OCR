# S1-1 票据样本集与标注规范 — 设计（spec）

> 任务卡：`docs/OCR票据识别与加密系统-AI协作开发实施计划.md` 的 S1-1
> 上游契约：`docs/EVAL.md`（数据集登记与指标口径）、`docs/SCHEMA.md`（12 个字段的枚举与类型）
> 状态：**待确认**（AGENTS §11：spec 与 plan 经确认后才写码）

## 1. 目标

产出一套**可复现、可评测、不碰个人信息**的票据数据集与标注，用于：

1. S1-2~S1-6 的预处理、检测识别、字段抽取、指标计算的开发与调试；
2. S6 的对比实验与消融实验（同一测试集上比较不同配置）；
3. 论文第 6 章的"数据集"一节（能写清来源、规模、标注方式、合规处理）。

**非目标**：不追求"覆盖所有真实票种"，不训练模型（微调是可选加分项），不收集师生真实票据。

### 2.2 为什么以合成为主

| 维度 | 真实票据 | 合成票据 |
|---|---|---|
| 可得性 | 受授权与隐私限制，规模上不去 | 可无限生成 |
| 标注成本 | 需人工逐字段标注（一张 2–5 分钟） | **生成时即精确已知**（零标注成本、零标注错误） |
| 可控性 | 无法控制光照/版式/票种 | 可逐个维度控制（做消融的必要条件） |
| 真实性 | 真实 | 版式与字体是"拟真"，分布有偏 |

结论：**合成集承担开发与实验，真实样本承担"域外泛化"与"预处理真实性"验证**，两者在论文里分开报告。

## 3. 票种与模板设计

5 类版式，覆盖"横版 A4 票"「竖条票」「竖屏截图票」三种形态：

| type_code | 名称 | 画布（宽×高） | 版式要点 |
|---|---|---|---|
| `vat_general` | 增值税电子普通发票 | 1200 × 800（横版） | 标题居中 + 发票代码/号码/开票日期 + 购销方四行 + 明细表格 + 合计/小写大写 + 校验码 + 红色圆章 |
| `train_ticket` | 铁路电子客票 | 600 × 1000（竖条） | 车次/出发-到达/日期时间/席位/票价/乘车人（**姓名走脱敏假名**）+ 二维码占位 |
| `flight_itinerary` | 航空运输电子客票行程单 | 1200 × 700（横版） | 旅客/身份证号（**假号**）/航班/承运人/票价/民航发展基金/合计 |
| `taxi_ticket` | 出租车票（定额） | 480 × 300（小票） | 发票代码/号码/日期/金额/车牌 + 极简布局（低分辨率、小字号，用来测**小目标检测**） |
| `e_invoice_portrait` | 全电发票（竖屏截图） | 1080 × 1920（9:16） | 仿手机屏幕截图：状态栏占位 + 票面主体 + 竖排表单；用于对齐真实样本的"竖版"形态 |

> 说明：`e_invoice_portrait` 不是"第六类票种"，而是 `vat_general` 的**截图形态**；
> 标注里 `ticket_type` 仍记 `vat_general`，另用 `form_factor: "portrait_screenshot"` 区分。
> 这样票种识别任务仍是 4 类 + unknown，形态差异留给预处理与鲁棒性实验。

## 4. 字段清单（与 SCHEMA.md / 方案 6.3 一致，12 个）

字段名以下划线形式与 `invoice_fields.field_name` **完全一致**（避免后期映射表）：

| # | field_name | 说明 | 校验规则（S1-5 实现） | 出现在 |
|---|---|---|---|---|
| 1 | `invoice_code` | 发票代码 | 10 或 12 位数字 | vat / taxi |
| 2 | `invoice_no` | 发票号码 | 8 位数字 | vat / taxi |
| 3 | `invoice_date` | 开票日期 | 合法日期，2015-01-01 ~ 今天+1 | 全部 |
| 4 | `buyer_name` | 购买方名称 | 2–100 字，非纯数字 | vat / flight |
| 5 | `buyer_tax_no` | 购买方税号 | 15/18/20 位；18 位走 GB 32100 校验位 | vat / flight |
| 6 | `seller_name` | 销售方名称 | 同 4 | vat / taxi |
| 7 | `seller_tax_no` | 销售方税号 | 同 5 | vat |
| 8 | `amount` | 金额（不含税） | 两位小数，Decimal | vat |
| 9 | `tax_amount` | 税额 | 两位小数 | vat |
| 10 | `total_amount` | 价税合计 | == amount + tax（容差 0.01）；大写金额需一致 | vat / train / flight / taxi |
| 11 | `check_code` | 校验码 | 20 位数字（可缺失） | vat |
| 12 | `passenger_name` | 乘车人/旅客（**假名**） | 2–20 字 | train / flight |

**合成时的健全性约束**（保证标注自洽，否则评测无意义）：

- `total_amount = amount + tax_amount`，且三位数的`三处金额`都由同一组数值派生；
- 大写金额由小写金额**程序生成**（不是手写常量），避免"大小写不一致"的低级错误污染标注；
- 18 位税号、20 位校验码、8 位号码、10/12 位代码都按规则**生成合法值**；
- 真实姓名字段一律用固定假名池（张伟/李娜/…），身份证号用**校验位合法但非真实**的号码。

## 5. 标注格式（JSONL，一行一张票）

```json
{
  "image": "samples/synth_v1/vat_general_0001.jpg",
  "ticket_type": "vat_general",
  "form_factor": "landscape",
  "width": 1200,
  "height": 800,
  "annotator": "synth",
  "seed": 20261118,
  "perturbations": ["rotate", "perspective", "illumination", "noise", "seal"],
  "boxes": [
    {"label": "invoice_code", "text": "042001900111", "bbox": [40, 120, 300, 152], "line_no": 0},
    {"label": "table_row",    "text": "办公用品",      "bbox": [60, 380, 460, 410], "line_no": 1}
  ],
  "fields": {
    "invoice_code": {"text": "042001900111", "value": "042001900111", "box_index": 0},
    "total_amount": {"text": "¥1,234.56", "value": "1234.56", "box_index": 7}
  }
}
```

约定：

- `bbox` 一律 **`[x1,y1,x2,y2]` 左上-右下、原图坐标**（与 AGENTS §5 的字段层格式一致；检测训练用的四点坐标由 `box` 派生，不在 JSONL 里重复存）；
- `label` 取**字段名**（12 个之一）或版式标签（`title` / `table_header` / `table_row` / `seal_zone` / `qrcode` / `footer`）——检测阶段只用 `boxes`，抽取阶段用 `fields`；
- `fields[x].value` 是**归一值**（金额 `1234.56`、日期 `2026-11-18`），`text` 是票面原样（含 `¥`、逗号、`年/月/日`）；
- `box_index` 指向 `boxes` 数组下标，保证"字段 ↔ 文本框"可追溯（`check_annotations.py` 会校验）；
- 标注由**生成参数直接产出**（先定字段值 → 再排版 → 记录绘制坐标），不存在"画完再回填"的错位风险。

## 6. 扰动设计（防止指标虚高）

任务卡明确：合成样本必须故意含倾斜、阴影、印章遮挡，否则指标虚高、S6 消融结论会被推翻。

| 扰动 | 参数范围 | 目的 |
|---|---|---|
| 旋转 | ±1° ~ ±6° | 手机拍摄不水平 |
| 透视 | 四角各偏移画布的 0–4% | 斜拍梯形畸变 |
| 光照 | 线性渐变（0.55–1.0 倍）+ 随机阴影椭圆 | 阴影/局部欠曝，对齐真实样本（灰度均值 129、偏暗） |
| 色偏 | 红/蓝通道增益 0.85–1.15 | 对齐真实样本的强红偏 |
| 噪声 | 高斯 σ = 2–8 | 手机夜景噪点 |
| 模糊 | 高斯核 0 / 0.8 / 1.5 | 手抖/失焦 |
| 印章 | 圆形红章，随机位置，**覆盖 5%–15% 的文本区** | 遮挡（真实痛点） |
| 折痕 | 1–2 条浅色直线 | 折叠痕迹 |

每张票随机组合，且**至少一项必须生效**（纯干净样本只保留 2 张作为"上限对照"）。

## 9. 验收标准（可自动验证，不依赖"人眼看图"）

因为开发环境里**无法直接看图**（模型不支持图像输入），验收必须做成程序可判定的。
实现见 `scripts/verify_samples.py`。

1. **渲染一致性**：用**局部自适应墨迹掩码**（比邻域背景暗 22 灰阶的像素）统计
   `fields[x].bbox` 内的墨迹率，要求 ≥0.02 且 ≥ 同尺寸随机框的 **3 倍**。
   *为什么不用"全局暗像素"*：样本里有深色背景、欠曝、红偏，"绝对暗"在不同图上含义完全不同，
   首版用全局阈值时随机框的暗像素率高达 0.337，判据失效（实测踩到）。
2. **可读性**：用系统 OCR（`scripts/ocr_probe.ps1`，Windows.Media.Ocr）识别合成图，
   计算**字段值命中率**——字段的归一值或票面原样，其归一化文本是 OCR 文本的子串，
   或最长公共子串覆盖其 ≥80%。干净组 ≥ **0.85**、困难组 ≥ **0.5**。
   *为什么不是整页字符相似度*：键名、表头、页脚读错不影响抽取任务；
   而"每个字段的值能不能读出来"才是下游真正依赖的性质（首版用整页相似度时，分母里混入了大量无关字符）。
3. **标注自洽**：`check_annotations.py --strict` 全过（格式、bbox 界内、`fields` 可回溯到 `boxes`、
   金额三件套等式、税号校验位、`invoice_code`/`invoice_no`/`check_code` 位数、无重复图、票种在两侧都出现）。
4. **成像覆盖**：真实样本的三项统计要落在合成集 P5–P95 内，且合成集里至少 3 张红偏 ≥15%、
   红偏最大值 ≥25%。*为什么不再要求"与真实样本误差 ≤40%"*：真实样本是**单个**最难工况
   （纸面仅占 30%、强红偏），强行让 40 张都长成那样既不真实也会让早期开发无法调试；
   改成"覆盖 + 含最困难档"更符合目的，论文里也会如实说明。
5. **划分完整**：dev ≥20 / test ≥12、两侧都覆盖 4 类票种、图像哈希不重复。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 合成版式与真实票差太远，S6 指标虚高、答辩被质疑 | 用真实样本对齐成像统计（§9.4）；论文如实写"合成集为主、真实样本仅 1 张做定性对照" |
| 字体缺失导致中文变方块 | 启动时探测系统字体（`msyh.ttc` / `simsun.ttc`），缺失直接报错并给出安装建议 |
| 标注与像素错位 | 先定值再排版，坐标来自绘制过程（§5 末条），并用 §9.1 自动校验 |
| 40 张太少、统计不显著 | 论文只做"配置间相对比较"与"定性展示"，不宣称绝对准确率；S6 若需要可扩到 100 张（脚本支持 `--n`） |
| 真实票据合规 | 图片不入库、票面文字不进日志、演示前脱敏（§2.1） |

## 11. 不做的事（范围边界）

- 不训练/微调检测识别模型（微调列在"可选加分项"）；
- 不做中英文混排、手写体、增值税专用发票、卷式发票的版式；
- 不生成二维码的真实内容（只画占位方块，避免造出可扫的假发票号）；
- 不收集第二张真实票据（1 张足够做定性对照）。
