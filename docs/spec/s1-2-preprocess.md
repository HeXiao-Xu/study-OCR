> 状态：**待确认**（AGENTS §11：spec 与 plan 经确认后写码）

## 1. 目标与非目标

**目标**：让任意来源的票据图（手机横拍/竖拍/斜拍/带桌面背景/偏暗/有印章）进入一个**统一、可复现**的形态，
供 S1-3 的检测识别使用；**处理失败也必须降级并打标，绝不抛异常中断流水线**。

**非目标**：
- 不做去印章/去折痕的修复（只标记，见 §3.6）；
- 不做超分辨率、不做去模糊模型（只做基础滤波）；
- 不训练任何模型（纯 OpenCV 规则）；
- 不做票据真伪鉴别。

## 2. 输入输出契约（🔴 本设计最关键的一条）

```python
preprocess(
    source: str | Path | bytes | np.ndarray,
    *,
    exif: bool = True,
    resize: bool = True,
    denoise: bool = True,
    rectify: bool = True,      # 四角点 + 透视
    rotate: bool = True,       # 残差小角度
    illum: bool = True,
    detect_seal: bool = True,
    binarize: bool = False,    # 默认关（见 §3.7）
    max_side: int = 1600,
) -> PreprocessResult
```

```python
@dataclass
class PreprocessResult:
    image: np.ndarray            # BGR，已校正；S1-3 直接吃这个
    original_size: tuple[int, int]   # (宽, 高) 原图
    quality_flag: Literal["ok", "low"]
    quality: QualityMetrics      # 见 §4
    quad: list[list[float]] | None   # 原图坐标系下的四角点（顺时针，可为 None）
    rotate_deg: float
    seal_boxes: list[tuple[int, int, int, int]]   # 原图坐标系
    warnings: list[str]
    steps: dict[str, bool]       # 每一步是否真的执行了
    timings_ms: dict[str, float]
    to_original: np.ndarray      # 3×3 单应矩阵：校正图坐标 → 原图坐标
    scale: float                 # 预处理缩放比（原图 → 处理图）
```

**为什么必须有 `to_original`**：
S1-3 在**校正图**上做检测识别，但前端要拿**原图**显示高亮框（用户看到的必须是自己的照片）。
没有这个矩阵，前端要么把校正图当原图（框整体偏移），要么在两层坐标间手写换算（必然出错）。
一张图返回一个矩阵，`.dot([x, y, 1])` 即可把任意框映回原图 —— 这是 S3-5 核对页能对上的前提。

**坐标约定**（AGENTS §5）：框一律 `[x1,y1,x2,y2]`；`quad`/`seal_boxes` 都在**原图坐标系**。

## 3. 处理步骤（每一步都可单独关闭，供 S6 消融）

### 3.1 EXIF 方向修正（必须最先）

- `PIL.ImageOps.exif_transpose`，然后转 BGR ndarray。
- **不做这一步，后面全错**（手机竖向拍摄的图会躺倒，检测框全乱）。
- 记录 `exif_applied: bool` 与旋转角度（90/180/270）。

### 3.2 缩放与灰度

- 长边 > `max_side`（默认 1600）时等比缩小；`scale` 记入结果，用于坐标回算。
- 灰度图只作为**中间产物**（定位、质量评估用）；送给 S1-3 的仍是 **BGR 彩色图**。

### 3.3 票据定位（轮廓法）

```
灰度 → 高斯模糊(5×5) → Canny(50,150) → 形态学闭(7×7, 2 次)
     → findContours(RETR_EXTERNAL) → 按面积降序取前 5 个
     → approxPolyDP(ε = 0.02·周长)
     → 第一个"近似 4 点 + 凸 + 面积占比 ≥ 35% + 内角 ∈ [50°,130°]"的轮廓胜出
```

四角点排序：按 `x+y` / `y-x` 取左上、右上、右下、左下（保证顺时针）。

### 3.4 透视校正与降级链（绝不抛异常）

| 顺序 | 手段 | 成功条件 | 失败后 |
|---|---|---|---|
| ① | 轮廓法四角点 + `getPerspectiveTransform` + `warpPerspective` | 通过 §3.3 的四项几何校验 | 进 ② |
| ② | `minAreaRect` 取最小外接矩形 → 只做旋转校正（不修透视） | 面积占比 ≥ 25% | 进 ③ |
| ③ | **原图直送** + `quality_flag="low"` + `warnings=["rectify_failed"]` | — | — |

- 输出尺寸按四边形边长估算（避免拉伸变形）：`w = max(上边, 下边)`、`h = max(左边, 右边)`，再按 `max_side` 收敛。
- 三种情况都要更新 `to_original`（①②③ 各对应一个不同的矩阵）。

### 3.5 残差小角度校正

- 用 `minAreaRect` 或 Hough 求主方向，`|角度| > 1.5°` 才旋转（避免把小噪声当倾斜）。
- 旋转后再更新一次 `to_original`。

### 3.6 照度校正

- 背景估计：大核形态学闭运算（`kernel = max(15, 长边//40)`，取奇数）→ `图像 / 背景 × 均值`。
- 备选/组合：`CLAHE(clipLimit=2.0, tileGridSize=(8,8))` 作用在 L 通道。
- **只做温和校正**：目标是把"阴影/渐变"拉平，不追求视觉上完美；过度校正会损伤低对比度的小字。

### 3.7 二值化：默认关闭

DBNet 用**自然彩色图**训练，强二值化是分布外输入，实测会掉检测率（S6 会用消融证明）。
因此 `binarize` 默认 `False`，只在"印章分离/笔迹分析"这类支路里用。

### 3.8 印章定位：只标记不修复

- HSV 双区间掩膜（红 `H∈[0,10]∪[170,180]`、蓝 `H∈[100,130]`）+ 开运算去噪 → 连通域 → 面积 ≥ 0.3% 的记为印章区。
- **不做 inpaint**：修补会啃掉笔画（任务卡明确列为坑）。
- 输出 `seal_boxes`（原图坐标）+ `seal_ratio`（占图面积比）。

## 4. 质量评估（决定 `quality_flag`）

| 指标 | 计算 | 判为 low 的阈值 |
|---|---|---|
| 亮度 | 灰度均值 | < 60（过暗）或 > 235（过曝） |
| 对比度 | 灰度标准差 | < 25 |
| 清晰度 | Laplacian 方差 | < 80 |
| 印章覆盖 | `seal_ratio` | > 5% 只记 warning，不单独判 low |
| 定位失败 | 降级链走到 ③ | 直接 low |

`quality_flag="low"` 不阻断后续识别，只是给前端/任务层一个"这张要重点人工核对"的信号（S3-2 的置信度会用到）。

## 5. 配置与默认值

写在 `PreprocessOptions`（dataclass）里，全部可覆盖；由 `Settings` 暴露两个常用项（`ocr_max_side`、`ocr_preprocess_enable`），
其余留给 S6 的消融配置直接传参。**禁止把这些阈值散落在代码里的魔法数字**。

## 6. 性能预算（CPU，1080×1920 输入）

| 步骤 | 预算 |
|---|---|
| EXIF + 载入 + 缩放 | ≤ 60 ms |
| 定位 + 透视 | ≤ 120 ms |
| 照度 | ≤ 60 ms |
| 印章 | ≤ 40 ms |
| **合计** | **≤ 300 ms**（对应《完整方案》7.7） |

超预算时：优先降 `max_side`（1600 → 1280），而不是砍步骤。

## 7. 验收（程序化，不依赖"人眼看图"）

开发环境无法看图，所以"不躺倒不扭曲"必须翻译成可判定断言：

1. **单测（边界与降级）**：
   - 无四边形（纯色图 / 噪点图）→ 走兜底、不抛异常、`quality_flag="low"`；
   - 超小图（80×60）→ 不崩，`max_side` 不放大；
   - 带 EXIF `Orientation=6`（旋转 90°）的 JPEG → 输出宽高互换、内容不躺倒；
   - 已知四角点的合成图 → 校正后四角点映射到图像四角（误差 ≤ 2% 边长）；
2. **坐标映射**：`to_original` 把校正图上的已知角点映回原图，与 `quad` 的误差 ≤ 2% 边长；
3. **数据集回归（60 张）**：
   - 定位成功率 ≥ 70%（合成集有 15% 无背景、若干远景，允许失败）；
   - `quality_flag` 分布与耗时 P95 记入 `docs/PROGRESS.md`；
4. **端到端增益（最强证据）**：对 `verify_samples.py` 抽出的困难样本，
   **预处理前后各跑一次系统 OCR**，字段命中率应**提升或持平**（若下降说明预处理把字弄坏了）；
5. **消融冒烟**：8 种开关组合各跑 3 张，全部不抛异常。

## 8. 实现期修正（代码已验证，spec 同步更新）

写码 + 用 OCR 前后对比做验收时，发现 spec 原稿有四处需要改。每一处都有实测依据：

| # | spec 原稿 | 实际做法 | 为什么改 |
|---|---|---|---|
| 1 | 面积占比阈值 35% | **18%** | 真实手机拍摄常见"纸面只占画面 20–35%"（S1-1 的远景档就是这样）。35% 会把 23/60 张直接判失败 |
| 2 | 在缩放后的图上做透视重采样 | **检测在小图、重采样在原图** | 先缩放再裁切会压缩纸面像素密度，字变小。实测某张票 OCR 命中率从 56% 掉到 **0%**；改成原图重采样后恢复 56% |
| 3 | 四角点就做透视 | 增加**恒等快捷**：四角点≈图像四角（±0.5%）时**不重采样** | 2 处样本本来就在正视角满幅，多一次透视插值把加粗的"票价"数字抹花，OCR 100%→67% |
| 4 | 照度校正"背景相除、目标取中位数" | 目标取 **p90**，增益**限幅 0.75–1.6 且只施加 70%** | 深色背景下中位数落在桌面那一档，取中位数会把整图压暗（实测 contrast 84→9.5）；限幅是因为过冲把浅灰小票提成一片白，OCR 认错字（seller_name 100%→67%） |
| 5 | 过曝用"均值 > 235"判定 | 用**饱和像素（≥250）占比**，阈值 0.95 | 白底文件均值本来就有 235–245，用均值判会把正常白底全标成 low |
| 6 | —（新增） | `warp_max_side=2400`、`min_side=0` | 校正后的长边上限比检测上限更宽松，**不缩小纸面**；小票放大不增加信息，默认关 |

验收口径也随之明确：`preprocess_eval.py` 只统计"原图本身可读（命中率 ≥50%）"的样本，
因为原图就读不出的样本（字高只有 8–10px）OCR 结果在噪声水平，前后对比没有意义——**如实单列，不混进平均**。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 轮廓法把"表格线框"当成票据边界 | 面积占比阈值 35% + 内角约束；并优先选最外层轮廓 |
| 合成集的桌面背景颜色与纸张接近 → 定位失败 | 失败即降级并打标（这正是真实场景的常态）；S6 用定位成功率说明局限 |
| 照度校正把小字洗掉 | 只做除法归一化，不做伽马拉伸；用 OCR 前后对比守住"不能变差" |
| 透视校正后比例失真实（估算尺寸错） | 用边长估算而非固定输出尺寸；单测覆盖"长宽比保持" |
| Windows 上 cv2 与 numpy 版本冲突 | 已锁 `opencv-python==4.6.0.66` + `numpy==1.26.4`（D-025） |

## 10. 不做的事

- 不引 `UVDoc`/`DocTr++` 这类文档矫正模型（要下载模型、CPU 慢；毕设工期不划算，列为展望）；
- 不做自适应裁剪到"仅票面"（保留少量背景更利于后续检测的上下文）；
- 不做多票据同图切分（一张图一张票，方案范围外）。

## 11. 输入分流与"重拍闸门"（2026-11-19 追加，D-035）

**PDF 电子发票不做预处理。** 电子件由税务端/开票系统导出，本身端正、无桌面背景、无阴影；
S1-6 的对照实验已经量到：预处理让检测 Hmean 从 0.974 掉到 0.948。所以 PDF 只**渲染成图**
（PyMuPDF，250 DPI），跳过 EXIF/定位/透视/照度/印章全部步骤。

**拍照件才走预处理**，并且给用户两类反馈：
1. **拍前引导**（`intake.PHOTO_GUIDE`）：平铺、四角入镜、正对拍摄、光线均匀、不要闪光灯；
2. **拍后结论**（`PreprocessResult.needs_retake` + `retake_hints`）：糊/暗/低对比/过曝/认不出边界/
   边缘贴画面 → 明确提示"请重拍"，并说明怎么拍。**不阻断流水线**，用户坚持使用也可以继续（人工核对兜底）。

对外统一入口是 `app/ocr/intake.py::prepare_input()`，调用方不需要感知输入形态：
```python
PreparedInput(image, kind="pdf"|"photo", preprocessed, needs_retake, retake_hints, page_count, notes)
```
按**魔数**判断 PDF（用户把 PDF 存成 .png 很常见），不看扩展名。

**透视安全边距**：四角点只要比真实纸面小 4%，warp 就会把贴边的字切掉（实测行程单 007：
1200 宽只剩 1101，左右各丢 ~50px）。所以 warp 前把四角点向外扩 2%，宁可多留一点桌面背景。

**四角点校验收紧**：对边长度差从 60% 收到 **30%**、内角范围从 [50°,130°] 收到 [55°,125°]。
同一张 007 原来被检成"上下边 685 vs 1106"的错切四边形，warp 出来整页是斜的；收紧后落到
`minAreaRect` 兜底，输出与原图同尺寸、零裁切。
