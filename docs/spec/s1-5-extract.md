# S1-5 关键字锚定 + 规则字段抽取 + 校验 — 设计（spec）

> 任务卡：S1-5 ｜ 上游：S1-3 的 `OcrLine`、S1-4 的票种与区域 ｜ 下游：S3 核对页、S6 评测
> 状态：已实现（按用户"继续"直接实现；要改的点直接说，我回退）

## 1. 目标
从文本行里抽出 12 个字段（金额三件套、税号、号码、日期、名称等），**并独立校验其合法性**。
抽取与校验严格分离：抽取器只给值 + 置信度 + 来源行号，校验器只报告问题，**不静默修正**（AGENTS §10.3）。

## 2. 规则（`templates/field_rules.yaml`）

每条规则显式声明：

| 键 | 含义 |
|---|---|
| `anchors` | 锚点同义词，**书写顺序即优先级**（越靠前越可信） |
| `direction` | `right` 同行右侧 / `below` 下方 / `any` |
| `regex` | 值的形态约束（提取时也用它切值） |
| `max_distance` | 锚点到值的最大距离（右取水平、下取垂直，**不是曼哈顿距离**） |
| `zone` | 允许出现的归一化纵向区间（躲开表头里的"金额/税额/名称"列名） |
| `value_index` | 一行/一组里有多个数值时取第几个（合计行的 金额 / 税额） |
| `occurrence` | `all`（默认，用于发现冲突）/ `first` / `last` |
| `exclude` | 含这些词的行不参与锚定（"项目名称"会把"名称"锚点带跑） |
| `whole_line_anchors` | 命中这些锚点时整行即值（出租车票只有一行公司名，没有标签） |
| `if_multiple` | 多处候选的显式消解（`max`） |
| `tickets` | 仅这些票种适用（数电票没有"校验码"） |

> **禁止"取最后一行的金额"这类模糊规则**（任务卡明确列的坑）——所有消解都是显式声明的。

## 3. 抽取流程

1. 按规则优先级逐条锚点找行（**锚点匹配忽略 OCR 插入的空格**："金 额""铁 路"很常见）；
2. 同行取锚点右侧 → 取不到再按方向/距离找邻近行（支持跨行累积 `value_index`）；
3. 归一化：金额→Decimal 字符串、日期→ISO、号码→纯数字、税号→大写去空格；
4. **冲突消解顺序**：锚点优先级 > 显式规则（`value_index` / `if_multiple`）> 报冲突；
   只有**同优先级证据矛盾**才记冲突，并保留 `candidates` 让前端选，**绝不静默替换**。

## 4. 校验（`validators.py`，全部纯函数 + Decimal）

| 校验 | 规则 |
|---|---|
| 金额三件套 | `total == amount + tax`，容差 `0.01`（缺税额时退化为 `total ≥ amount`） |
| 大写金额 | 解析"壹仟贰佰…元伍角陆分"，与小写**完全一致**（容差 0：差 0.01 就是读错） |
| 日期 | 可解析、不晚于今天、不早于 2000 年 |
| 发票代码 | 10 或 12 位数字 |
| 发票号码 | 数电票 20 位、其余 8 位 |
| 统一社会信用代码 | 18 位、字符集 `0123456789ABCDEFGHJKLMNPQRTUWXY`（剔除 I/O/S/V/Z）、GB 32100 校验位 |

校验失败：`errors[]` 返回原因，并把该字段**置信度折半**（任务卡要求），**不抛异常**。

## 5. 实测（60 张合成集）

总体 **368/430 = 85.6%**：

| 强项 | 准确率 | 弱项 | 准确率 |
|---|---|---|---|
| check_code | 100% | tax_amount | 56.7% |
| invoice_code | 96.7% | amount | 60.0% |
| invoice_date | 96.7% | total_amount | 76.7% |
| invoice_no | 95.0% | seller_name | 86.0% |
| buyer_name | 93.3% | buyer_tax_no | 86.7% |

## 6. 已知短板与原因（如实记录）

| 短板 | 原因 | 后续 |
|---|---|---|
| amount / tax 漏抽 10 张 | 主要是旧版票**竖屏截图**：合计行与金额分成两行、且被印章遮挡，锚点邻域内取不到 | S1-6 前可加"按列对齐"的表结构解析 |
| total_amount 错 11 张 | 合计行未被检出时退到"金额"锚点，取到明细金额 | 用 `amount + tax` 交叉校验来择优（下轮） |
| seller_name 错 7 张 | 部分票公司名无标签，靠"有限公司"整行兜底，偶发取到买方 | 结合区域（seller 在 buyer 之后）约束 |

## 7. 不做
- 不接 LLM 兜字段（成本高、不可复现，S6 要的是规则基线）；
- 不做表格行列还原（本轮用锚点 + 坐标邻近已够）；
- 不在抽取器里改值（冲突一律留给人工）。
